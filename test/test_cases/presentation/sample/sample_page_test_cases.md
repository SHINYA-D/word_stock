## 実行環境について

SampleViewModel はサブクラスでの状態 override を行わず、`sampleRepositoryProvider` を
`test/helpers/fake_infrastructure.dart` の `FakeSampleRepository`（失敗キュー・`Completer` のゲート・
`getResponses` の呼び出し順キュー・呼び出し記録を持つ手書きフェイク）に差し替え、本物の
`SampleViewModel` をそのまま動かして検証する。
BottomNav・`/folder/:folderId`・`/login` への画面遷移、端末の戻る操作（`tester.binding.handlePopRoute()`）を
確認するテストは、アプリ本体の `router.dart` には依存せず、`ShellPage` を含む最小限のテスト専用
`GoRouter`（`buildSampleApp`）を用いる。
4章（ViewModel の状態）は `test/presentation/sample/sample_view_model_test.dart`（別ファイル）の担当のため、
本ファイルでは画面で観測できる結果（表示・ダイアログ・スナックバー・遷移）のみを確認する。

本ファイルは承認済み仕様書 `docs/detailed_design/presentation/sample/sample_page.md` の
2.2（SMP-N01〜N04）・3章（SMP-D/C/U/X/T/E）の全 113 ID を担当する。4章（SMP-V）・5章（SMP-R）は
`sample_view_model_test.dart` の担当のため対象外。

## 仕様と前提データが違うケース（忠実さレビューでの指摘）

- **SMP-D27**: 仕様の前提データは「A」「B」の2件（隣接する2行）だが、テストは
  `[A, C1, C2, C3, B]` の5件にして「B」役を離れた行にしている。A の直後の行だと
  メニューのオーバーレイと物理的に重なり、タップが別の要素に当たってしまうため。
  **隣接行でのメニューの重なりは現行 UI の制約上テストしていない。**
