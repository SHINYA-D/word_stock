# サンプル画面 振る舞い仕様書

## 1. 機能概要

テスト専用の画面。サンプル（名前だけを持つアイテム）の一覧表示・作成・名前の編集・削除ができる。
ボトムナビゲーションバーの「テスト」タブ（`/sample`）から開く。

## 2. データ定義

### 2.1 Sample

| 項目 | 型 | 説明 |
|------|----|------|
| id | String | サンプルの識別子。Repository が採番する |
| name | String | サンプル名。2.2 の入力ルールを満たす |
| createdAt | DateTime | 作成日時 |
| updatedAt | DateTime | 最終更新日時 |

### 2.2 入力ルール

SMP-N01〜N04 は作成ダイアログ、SMP-N05〜N08 は編集ダイアログの入力欄のルール（内容は同じ。1 ID = 1 対象にするため分けている）。
編集ダイアログの境界値は、初期値「A」の入力欄を空にしてから入力した値とする。
幅は半角文字を1、全角文字（かな・カナ・漢字・全角英数記号・全角スペース）を2として数える。

### 3.6 エラー種別ごとの扱い

3.1〜3.4 で代表として書いた `UnknownFailure` 以外を、操作ごとに書く。
`NetworkErrorDialog` を表示するのは一覧の初期読み込みの失敗だけ。プルして更新・作成・変更・削除の失敗は、Failure の種類に関わらずスナックバーで伝える。
`NetworkErrorDialog` には「通信エラー」「通信に失敗しました。\nログイン画面に戻ります。」「OK」が表示される（現行UI）。

## 7. 対象外

- 作成の `NotFoundFailure`: 作成には変更・削除の対象がなく、発生しない
- 削除の `NotFoundFailure`: 対象が存在しなくても `Right(unit)` を返す（SMP-R11）ため、発生しない
- 削除の処理中に同じサンプルをもう一度削除する操作: SMP-R11 により、二重に実行しても結果が変わらない
- 初期読み込みの `NetworkFailure` 以外（`AuthFailure`）で表示された `NetworkErrorDialog` の「OK」をタップした後の動作: ログアウトとログイン画面への移動は `NetworkErrorDialog` とルーターの共通の動作（原則-11）で、Failure による違いがない。この画面では SMP-E04 で1件だけ確認する
- プルして更新・作成・変更・削除の `NetworkFailure` / `AuthFailure` でのログアウト: この画面ではスナックバーで伝えるだけで、ログアウト・ログイン画面への移動は行わない（ユーザー決定 2026-09-22）。ログアウトしないことは画面から観測できないため、項目を作らない
- オフライン同期（`sync_queue` への登録・競合解決）: 概要設計書でテスト専用画面とされており、同期の振る舞いを定めない
- 一覧の各行の先頭アイコン・色・角丸などの装飾: 振る舞いがなく、見た目だけのため
- 絵文字など、2.2 の全角・半角の判定にない文字の幅: この仕様書では幅の数え方を定めない（ユーザー決定 2026-09-22）
